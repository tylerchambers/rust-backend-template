## Objective
Production-grade Rust SaaS modular monolith; pragmatic hexagonal architecture and explicit constructor injection.
## Cargo workspace
- crates/domain: aggregates, value objects, invariants, domain events; no IO.
- crates/application: commands, queries, use-case services, ports, authorization policies, unit-of-work contract.
- crates/infrastructure: PostgreSQL repositories, sessions, WebAuthn integration, Redis, River, email.
- crates/api: Axum routes, DTOs, middleware, OpenAPI.
- crates/bootstrap: concrete construction and configuration.
- apps/server, apps/worker, apps/cli: binary entrypoints.
## Port design
Use narrow ports where variation or testing needs justify them. Example conceptual APIs:
```rust
trait Clock { fn now(&self) -> OffsetDateTime; }
trait IdGenerator { fn new_organization_id(&self) -> OrganizationId; }
trait OrganizationRepository { /* get, insert, save; transaction-bound */ }
trait UnitOfWorkFactory { /* begin() -> transaction-scoped repositories; commit() */ }
trait InvitationEmailDispatcher { /* enqueue via River within active transaction */ }
trait Cache { /* namespaced get/set/invalidate with TTL */ }
```
Do not finalize UoW signatures before testing SQLx borrow/lifetime constraints; do not leak SQLx types into domain. Prefer generics for statically known dependencies; trait objects when runtime substitution is useful. Use typed domain errors and application error mapping. No global locator, auto-magic ORM, or repository trait per trivial entity.
## HTTP contracts
Axum handlers parse/validate DTOs, resolve trusted actor and tenant context, invoke application use cases, map errors to stable machine-readable responses. OpenAPI describes all endpoints; generate TypeScript client; check contract drift in CI. Version routes. No SQL or domain policy logic in controllers.
## Event model
Domain events are facts; River jobs are execution requests. Enqueue within the same SQLx transaction when River supports it. Keep an outbox only for independent external integration event publishing.
## Architectural tests
Fail CI on domain-\>infrastructure or domain-\>HTTP dependencies, SQL in controller modules, and bypass of use-case authorization. Agent may propose ADR if an exception is required.
## Completion
A fully working Project vertical slice demonstrates command, query, policy, UoW, SQLx adapter, RLS, API, OpenAPI, River job, unit and integration tests.
