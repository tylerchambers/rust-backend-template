## Tickets
### AUTH-01 — Implement email magic-link registration and login
**Status:** Not Started<br>**Objective:** Implement email magic links using CSPRNG tokens stored only as hashes, short TTL, atomic one-time consumption, rate limits, nonenumerating initiation, safe redirects and secret redaction. GET only renders confirmation; explicit CSRF-protected POST consumes the token and authenticates. Use an external email capture service in development and an SMTP adapter in production.<br>**Depends on:** DB-02, ARC-02<br>**Acceptance criteria:** Browser/integration tests cover first and returning login, expired/invalid tokens, concurrent replay, enumeration resistance, limits, unsafe redirects, CSRF and secret redaction; scanner GET cannot consume a link or create a session. Verify delivery through development capture and the production SMTP adapter in a test SMTP environment.<br>**Agent evidence:** PR/commit, commands executed, test results, ADR if design changed.<br>**Handoff:** Do not mark complete until tests and review evidence are linked.

### AUTH-03 — Implement fresh email reauthentication
**Status:** Not Started<br>**Objective:** Require a fresh email link to the current verified mailbox for sensitive operations, bound to user, session, action and target, with short TTL and atomic one-time consumption; enforce scanner-safe confirmation and the AUTH-01 token safeguards. Mailbox access is the trust anchor, not an independent second factor or hardware binding.<br>**Depends on:** AUTH-02<br>**Acceptance criteria:** Privileged action denied without fresh email proof; proof cannot authorize another user, session, action or target, survive expiry, or be replayed; GET cannot authenticate or execute the action.<br>**Agent evidence:** PR/commit, commands executed, test results, ADR if design changed.<br>**Handoff:** Do not mark complete until tests and review evidence are linked.
### AUTH-04 — Email identity lifecycle
**Status:** Not Started<br>**Objective:** Keep one verified primary login email per user; create or resolve the identity only after valid link confirmation, enforce normalized email uniqueness and account status, and audit identity/session lifecycle without secrets.
