All identifiers use typed Rust wrappers; PostgreSQL UUIDs (UUIDv7 preferred). UTC timestamptz. Unique memberships (organization_id,user_id), normalized email uniqueness, indexed tenant foreign keys. Use database constraints for durable invariants. Initially support one verified primary login email per user; no address-change or multiple-address workflow. Auth tokens have short expiry and atomic consume-if-unconsumed-and-unexpired semantics; purpose separates login from reauthentication, whose user/session/action/target bindings are required. Create/verify an identity and consume its login token atomically; do not persist raw tokens or add authenticator tables.
## Tenant isolation
- All tenant resources have organization_id; global user and email authentication token records do not.
- Enable and FORCE RLS where appropriate on tenant tables. App DB role lacks BYPASSRLS and table ownership bypass.
- Establish trusted tenant context using SET LOCAL / set_config(..., true) inside every scoped transaction, never session-level state on pooled connections.
- Policies use current_setting with missing-safe behavior and deny-by-default. Never trust organization_id supplied by caller as proof of authorization.
- Cross-tenant administrative jobs use separate reviewed execution path, not a universal bypass on API connections.
- Membership permissions evaluated in application; RLS is independent defense.
## Migrations
Timestamp-prefixed, immutable SQLx SQL migrations. Dedicated deploy migration command; do not auto-run migrations in each API replica. Verify checksums, clean install, upgrade from prior snapshot, indexes, FKs, constraints, RLS policy state, and migration ownership. For large tables use expand/contract and separate backfills. Maintain SQLx offline metadata in CI.
## Concurrency
Optimistic version check for mutable aggregates; conditional UPDATE version = expected_version and increment. Return conflict error on zero affected rows. Use explicit locks for invitation acceptance and last-owner changes.
## Security acceptance
Test direct SQL with two organizations; cross-tenant SELECT, UPDATE, DELETE fail. Verify transaction context clears on pooled connection reuse and failed transactions. Verify unscoped queries deny access; bypass role absent.
