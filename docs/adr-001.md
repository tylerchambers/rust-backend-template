# ADR 001: implementation boundaries and current deviations

## Authority and construction

The user replaced all WebAuthn/passkeys/recovery with single-primary-email magic links. No recovery or address-change endpoints exist. Mailbox compromise compromises login; mailbox loss has no application bypass. User overrides, then the updated Notion hub/RFCs, then this implementation govern.

The workspace dependency direction is server/worker/cli → bootstrap → API/application/infrastructure → domain. API invokes application services; SQL remains in infrastructure. Constructor injection supplies purpose-specific ports. A transaction-scoped unit of work implements organization, project and membership repositories and atomic River publication. Role checks remain in application; SQL locks and conditional writes preserve publication safety. Domain/application use distinct UserId, SessionId, OrganizationId, ProjectId and InvitationId wrappers. UUID transport and storage conversion stays at adapters. Injected IdGenerator supplies application-created aggregate IDs; injected Clock supplies invitation expiry. Database time remains authoritative for token/session/proof validity and final consumption, rather than trusting an application wall clock for security checks. Fixed-ID and fixed-clock integration tests constrain these contracts.

## Authentication

256-bit random tokens are SHA-256 hashed in PostgreSQL; raw tokens are not persisted in jobs, sessions, proof tables or logs. Login links place tokens in URL fragments; GET renders a confirmation page and does not consume them. POST requires exact Origin and double-submit CSRF. Secure HttpOnly __Host-session cookies have idle and absolute database expiry. Rotation retains revocation-only old-token handles; old tokens cannot authenticate. Privileged proof binds user, session, organization, action and target, and consumption shares the mutation transaction. Confirmation UI reveals the proof for the requesting API client; the privileged CSRF-protected POST performs consumption. This is mailbox proof, not a second factor.

### Review-resolved session and discovery contracts

Logout resolves immutable session identity in a separate statement before updating it. This avoids READ COMMITTED rechecks losing a concurrently inserted old-token handle. Handles revoke only; they never authenticate. Session lists include only nonrevoked, absolute-live and idle-live sessions. A role change (promotion or demotion, excluding a no-op) retires all existing credentials of the affected user in the same UoW as membership and audit publication. Login serializes on the affected user row; the user must sign in again. Other users remain signed in.

Initiation, confirmation and proof requests share a PostgreSQL socket-IP budget (120 per 15 minutes). Forwarded headers are never trusted: a reverse proxy is one peer and shares its budget unless a future explicitly authenticated proxy policy is implemented. Initiation additionally permits five normalized-mailbox requests per 15 minutes. Confirmation has a separate five-attempt mailbox budget derived from the token record, counting replay and failures; unknown tokens cannot identify a mailbox and are bounded by the socket budget. Redis is optional and does not replace PostgreSQL admission.

Organization discovery returns only the caller's memberships and organization name/role; member discovery requires current membership and returns IDs/roles, not email addresses. Both use exclusive UUID cursors and 50-row pages; use the last returned ID as the next cursor until an empty page. Project cursors have the same ordering semantics: a foreign ID does not authorize or reveal its tenant. No mutable active-tenant state is introduced. Migration 10 adds only SELECT self-discovery policies, using transaction-local validated-user context; ordinary tenant writes and FORCE RLS are unchanged.

Invitations are join grants, not alternate role changes. Acceptance by an existing member consumes the invitation but preserves their existing role. A regression covers an owner invitation accepted by an existing ordinary member.

SQLx errors at the auth/project/membership adapter boundary emit a closed operational category (connection, pool_closed, timeout, permission, transaction_conflict, constraint, other). The adapter is the single cause-logging owner; upstream error messages and debug values are discarded, and HTTP still exposes only the stable unavailable code.

## River compatibility spike (completed)

Current installed stable Rust 1.99.1, SQLx 0.9.0 and official riverqueue 0.6.0 compile together. Real PostgreSQL tests proved atomic business-write/job commit and rollback, actual Project index execution, leader-scheduled cleanup, SIGKILL/restart rescue and bounded retries to terminal discard. Tests accelerate only their own persisted attempt/schedule timestamps; River performs every transition. River owns migrations, leases, execution, retry state and schedules. No homegrown queue. River's cancellation-safe begin_postgres protects pooled transaction initialization.

Invitation jobs persist only tenant/invitation IDs. Delivery generates a fresh token, stores its hash, then sends via SMTP. A retry replaces the earlier hash. SMTP lacks idempotency: ambiguous delivery can send duplicate messages, and only the newest link remains valid. No exactly-once external delivery claim. Accepted/revoked/expired invitations are not resent. Project indexing is idempotent and tenant-scoped. Identity cleanup is the only global worker operation and does not bypass tenant RLS.

## Persistence and deployment

SQLx application migrations are immutable once applied. River migrations remain independent. Runtime refuses superuser, BYPASSRLS and table-owner credentials. Tenant transactions use transaction-local set_config and FORCE RLS; absent context denies access. Deploy credentials are separate. No API auto-migration. Current migrations create the shared template_app role and therefore assume a fresh dedicated PostgreSQL cluster for clean-install testing; multi-database installation in an already provisioned cluster needs a provisioning split.

## Optional Redis

PostgreSQL remains identity/session/membership authority and always provides login rate limits. Configured Redis adds a fail-closed distributed auth limiter; unavailable optional cache falls back to PostgreSQL. Project cache keys include environment and tenant, expire after 30 seconds, and invalidate after writes. Cached project lists are eventually consistent (including read/write races), never authoritative for authorization or concurrency decisions. Membership is checked against PostgreSQL before a cached read.

## Compatibility, telemetry and operational boundaries

Migration 9 adds nullable audit correlation without breaking the prior executable. The two-revision gate starts the original schema in a separate disposable PostgreSQL instance, creates live identity/session/tenant state, upgrades it, and exercises old/current binaries against the expanded schema. Old River payloads default missing correlation IDs; new jobs carry the actual HTTP request ID. JSON tracing spans and operational metrics are tested across native and OCI processes. No collector or production deployment is implied.

Built-in roles are a closed typed vocabulary stored as constrained membership values rather than configurable role/permission tables. One verified email lives on the global user rather than a multiple-address table; this deliberately matches the single-address/no-change scope. The generic proof target is a UUID paired with a closed validated action; business entity contracts otherwise use distinct ID types. Runtime adapters retain raw UUID wire/SQL shapes. No generic entity framework, DI container or bespoke queue was introduced.

The developer interface is just plus direct Python scripts; Python uses only the standard library for disposable lifecycle tooling, not a second application runtime. OpenAPI generation bundles openapi-typescript against its compatible TypeScript 6 compiler API while the SDK is checked with TypeScript 7. The actual generator/SDK behavior, not nominal version compatibility, is gated.
