# ADR 001: implementation boundaries and current deviations

## Authority and construction

The user replaced all WebAuthn/passkeys/recovery with single-primary-email magic links. No recovery or address-change endpoints exist. Mailbox compromise compromises login; mailbox loss has no application bypass. User overrides, then the updated Notion hub/RFCs, then this implementation govern.

The workspace dependency direction is server/worker/cli → bootstrap → API/application/infrastructure → domain. API invokes application services; SQL remains in infrastructure. Constructor injection supplies purpose-specific ports. A transaction-scoped unit of work implements organization, project and membership repositories and atomic River publication. Role checks remain in application; SQL locks and conditional writes preserve publication safety. UUIDv7 IDs are currently generated directly in application services; a fully injected ID/clock contract remains outstanding.

## Authentication

256-bit random tokens are SHA-256 hashed in PostgreSQL; raw tokens are not persisted in jobs, sessions, proof tables or logs. Login links place tokens in URL fragments; GET renders a confirmation page and does not consume them. POST requires exact Origin and double-submit CSRF. Secure HttpOnly __Host-session cookies have idle and absolute database expiry. Rotation retains revocation-only old-token handles; old tokens cannot authenticate. Privileged proof binds user, session, organization, action and target, and consumption shares the mutation transaction. Confirmation UI reveals the proof for the requesting API client; the privileged CSRF-protected POST performs consumption. This is mailbox proof, not a second factor.

## River compatibility spike (completed)

Current installed stable Rust 1.99.1, SQLx 0.9.0 and official riverqueue 0.6.0 compile together. Real PostgreSQL tests proved atomic business-write/job commit and rollback, actual Project index execution and leader-scheduled cleanup. River owns migrations, leases, execution, retry state and schedules. No homegrown queue. River's cancellation-safe begin_postgres protects pooled transaction initialization.

Invitation jobs persist only tenant/invitation IDs. Delivery generates a fresh token, stores its hash, then sends via SMTP. A retry replaces the earlier hash. SMTP lacks idempotency: ambiguous delivery can send duplicate messages, and only the newest link remains valid. No exactly-once external delivery claim. Accepted/revoked/expired invitations are not resent. Project indexing is idempotent and tenant-scoped. Identity cleanup is the only global worker operation and does not bypass tenant RLS.

## Persistence and deployment

SQLx application migrations are immutable once applied. River migrations remain independent. Runtime refuses superuser, BYPASSRLS and table-owner credentials. Tenant transactions use transaction-local set_config and FORCE RLS; absent context denies access. Deploy credentials are separate. No API auto-migration. Current migrations create the shared template_app role and therefore assume a fresh dedicated PostgreSQL cluster for clean-install testing; multi-database installation in an already provisioned cluster needs a provisioning split.

## Optional Redis

PostgreSQL remains identity/session/membership authority and always provides login rate limits. Configured Redis adds a fail-closed distributed auth limiter; unavailable optional cache falls back to PostgreSQL. Project cache keys include environment and tenant, expire after 30 seconds, and invalidate after writes. Cached project lists are eventually consistent (including read/write races), never authoritative for authorization or concurrency decisions. Membership is checked against PostgreSQL before a cached read.
